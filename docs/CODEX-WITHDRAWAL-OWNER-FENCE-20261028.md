# Withdrawal history and action owner fence

Withdrawal history and panel actions now send the current owner context marker and require the authenticated server response to match before using it. The server rejects a mismatched marker before parsing a POST body or accessing its database or provider. An observed mismatch or unavailable verification clears the visible account view without discarding a hidden signed packet. A fresh matching active record can recover the exact in-memory signature if tab storage is unavailable, after cryptographic revalidation; no registration or submission happens automatically.

The server keeps accepting requests without the marker for existing API clients, so this protection applies to the updated panel and clients that supply it; it does not replace authentication. Signed-in account changes after the last check cannot be made atomic with a browser interaction. Tab storage failure combined with unmount can still lose an unregistered packet. Existing signing, consent, submission and recovery rules are unchanged.

Independent synthetic verification passed 49 tests across three files covering history, pagination, account changes, all panel POST action families, stale/missing scope responses and recovery. A separate clean-dependency checkout ran the existing local D1 route and owner-scope tests: 37 passed, none skipped; its six copied files matched the active checkout by SHA-256 before and after. TypeScript, typed lint and formatting passed. Independent source review found no remaining blocker in this bounded change. No hosted database, credentials, provider calls, real wallet action, signing, funded trade or deployment was used.
