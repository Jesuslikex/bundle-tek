# Stock-pair unsigned simulation

15 October 2026. Extends the unsigned pair candidate checkpoint. This work remains local; production is source 34bcd9a.

## Runtime behavior

The owned pair-order candidate API now requires successful simulation of the exact canonical unsigned packet before returning a candidate. The RPC call uses the original recent blockhash, sigVerify=false, replaceRecentBlockhash=false, a minimum context slot and explicit base64 post-account snapshots for every resolved writable address. It never calls a signing or submission method. Simulation failures are sanitized and cannot return candidate bytes as a successful response. Saved source state, wallet balances/custody, mint policy, lookup-table identity, original blockhash lifetime and bounded slots are still checked after simulation.

The verifier decodes actual post-account bytes rather than accepting token delta labels from the order provider. It checks exact raw source consumption, minimum raw destination credit, both token programs' selected custody, required Token-2022 extensions, native system-wallet ownership and rent floor, account creation rent and native wrapping/refund conservation. Amount arithmetic stays in BigInt, including balances beyond Number precision. Other writable post-accounts cannot introduce unrelated wallet token custody, delegate/close authority or mint authority. Compute usage must fit the reviewed limit; optional simulation fee metadata must agree with the independent message fee.

Native SOL accounting combines the system wallet and selected WSOL account, so pre-existing WSOL balances/reserves and temporary-account refunds cannot be mistaken for trade proceeds. A closed native account must be absent or the canonical empty, zero-lamport, nonexecutable system-owned account. A retained WSOL account must preserve its exact previous reserve, or use the exact independently observed rent for a new account. Retained native and nonnative creation rent are reported separately and summed; neither is confused with token output or temporary refunded rent.

The result binds a digest of ordered post-account evidence and a structured simulation report into the existing candidate review digest and expiry. It reports economicSimulationVerified=true only after these observational checks. This is a provider-observed simulation, with signatureVerified=false, providerObservationOnly=true, programCodeAttested=false and no application reservations, approval, signing or execution authorization. Top-level assessment alone continues to report instructionsVerified=false. Simulation is not final settlement, a cryptographic validator attestation, an exhaustive inner-program audit or a guarantee that a later transaction will succeed.

## Remaining requested workflow

The economic checks cover the selected pair and system-wallet net state, not an inventory of every other protocol position. Runtime program/CPI qualification, including writable accounts that could control other assets such as nonce or stake positions, must remain a prerequisite before enabling signing. Currency-aware durable reservations, explicit user approval, browser signing, signed registration, broadcast/recovery, exact quote-asset settlement/accounting, stock-launch budget scaling and protected token-workspace UI remain required. Current SOL-only signing adapters have not been widened to consume these candidates. No UI, migration, remote database, credential/provider, cron, deployment or real wallet action is part of this increment. Main's two unrelated dirty files remain protected.
