# Warmup raw-account runtime collector

21 October 2026, base 51958c9. New internal collector and synthetic integration coverage. This is not a connected application runtime mode, automatic warmup, trusted-program approval or live qualification.

`lib/wallet-warmup-runtime-order.ts` observes the real mint and canonical wallet accounts before and after one call to the existing wallet-bound Jupiter order preparer. It builds a lower runtime context from those observations, without imported-project placeholders, and calls the existing full pair runtime collector with both complete code scans explicitly serial. Exactly one raw-account simulation is allowed. No legacy simulation is also run.

The input's domain-separated read-request digest is recomputed before RPC. It binds the exact captured wallet, mint, side, raw input, fee/rent reserve, deadline and prior Sell inventory. It is **not** an owned lease or user-consent hash. The collector does no database ownership/source/lease admission or write. A future server adapter must build this input from owned source data after the original immutable runtime-purpose claim, repeat source guards, and atomically retain the result with its matching outcome. No production route or provider factory imports this new collector; current importers are its test and synthetic fixture only. Existing application behavior remains unchanged.

## Preserved limits and truthful evidence

- No stock RPC scopes on either channel. Explicit injected account/code transports must be supplied together; otherwise both use the existing indexer selection and ordinary pacing. This preserves the indexer's existing configured-or-legacy-fallback behavior; it creates no provider setting or new public fallback. Source labels say selected runtime RPC, without exposing endpoints or credentials.
- Every actual response context, including the initial slot, pre-order mint/wallet reads and full code chunks, contributes to one 32-slot window and later floors. Prior Sell inventory's holdings and mint slots contribute too. Those prior slots are explicitly labelled caller-captured and not read within this collector.
- Actual Clock accounts use the ordinary exact-equality parser and existing 30-second wall-time rule. Duplicate Clocks must agree. **Code chunks do not request their own Clock:** they are covered by context-slot floors and the32-slot window. The result explicitly records `codeClockPolicy: context-slot-floor-only` and the actual account-channel Clock observations. Both channels being unscoped does not imply per-code-chunk Clock evidence.
- The cooperative budget ends at the earliest of the original deadline, start + 25 seconds and prior Sell inventory expiry. Cancellation aborts remaining reads and late results refuse. Accepted remote work cannot be undone by local cancellation. No polling or provider retry is added.
- Existing full packet, route/instruction, raw simulated account, custody, Rent, minimum-output, lifetime, network, lookup and final post-code rechecks are reused. Pair/group implementations, defaults, hashes, trust pins and signing gates are unchanged. Both code scans remain complete; no final scan is skipped or reused.
- The read-only method allowlist and300-call aggregate cap cover both channels. Account replies remain bounded at512 KiB and code replies at2 MiB, with the shared collector's unchanged per-request and per-slice byte/account limits. Simulation is unsigned, with no send or airdrop method.
- Sell inventory must have exact wallet/mint/input/decimals/program, strictly true coverage/support, consistent total/frozen/available raw amounts, a recent non-future observation and an unexpired original deadline. Fresh wallet/mint evidence still independently rechecks actual custody and balances. The inventory digest is consistency evidence, not independently verified provenance.
- Quoted fee/rent arithmetic and its reserve are checked before the full collector. Decoded actual account setup rent must fit the quoted rent, and the larger observed/quoted network fee plus that quoted rent must fit the original reserve. Underestimated provider costs refuse; amounts and budgets are never silently adjusted.
- The narrow unsigned summary is derived from the raw economic result. Native wallet changes and selected token amounts remain distinct; proven wrapped-account closure/preservation is projected exactly. Native trade/rent/refund observations remain in the runtime evidence rather than being presented as profit. Any nonzero auxiliary token delta refuses under warmup's stricter policy.
- The minimum is explicitly `order-self`, with independent price protection false. Code identity observation establishes neither semantic trust nor permission to sign. Summary binding status describes the full collector's custody checks, not execution of the legacy binding reader. Signing, execution, trusted-program policy and program attestation remain false.
