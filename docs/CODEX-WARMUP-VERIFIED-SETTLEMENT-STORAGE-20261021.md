## Actual integration

The new internal capture takes only a record UUID, owned journal UUID, exact expected version/head and an existing receipt UUID. It derives the pending captured action and exact saved/session-buy dependency from the admitted journal, requires submitted/unknown state, then calls the original real receipt replay adapter. The adapter independently checks the existing owned preparation/signing intent, packet/signature, mainnet genesis and finalized balance evidence, including the linked buy for a sell. No input settlement, source document, owner or capability flag is accepted from a request. A future HTTP caller must supply its owner from a verified session; this is not an authentication wrapper or mounted endpoint.

After verification, the capture builds a canonical small record envelope and keeps its exact raw source snapshot separately. A single `INSERT … SELECT … WHERE` includes all24-column source-fact comparisons for Buy or both rows for Sell. Source-only0125 repeats the typed live source comparison and exact captured-action/head constraints at insertion. Record, event and head changes happen in that one statement through the trigger, so a failed source predicate, competing predecessor or head update cannot leave a partial accounting transition. It uses no follow-up write batch whose other statements could commit after a zero-row condition.

Full original prefix replay with BigInt arithmetic decides whether the observed settlement fits the captured limits. The database CAS binds that decision to the unchanged prefix; it does not use SQLite integer/REAL casts to sum u64 amounts. An admitted outcome appends a proof-backed finalized event, charges the original input/fee/positive-rent budget once and retains the actual receipt identity. Rent refunds still cannot replenish reserve and sell proceeds still cannot fund another buy. An outcome the sequence refuses is retained as `held`, with `sequence-refused` rather than an invented specific diagnosis. Its proof-backed unknown event advances the history/head but leaves budget/completion unchanged and blocks new actions. Actual paid fees/units remain in the record for manual reconciliation; a zero recorded-budget delta is not a claim that no money was spent.

Both modes retain real verified facts. Neither starts an action or reserves funds. An invalid/unavailable provider result cannot become held evidence: verification fails before any write. Late valid outcomes stay recordable after Stop, preview expiry or current-plan archival/revision changes, without resuming a stopped session or renewing the original source window.

## Durable recovery and scope

Records are immutable against UPDATE, DELETE and INSERT OR REPLACE. Owner-scoped uniqueness covers the record ID, journal/action, receipt/side and original signature, preventing duplicate accounting through another retained view. Competing writers get one admitted original; a controlled conflict exposes only the existing owner's recovery ID, which may belong to another journal and must not be silently substituted into the current scope. There is exactly one INSERT attempt. Lost responses/cancellation recover that same ID with a bounded independent read; absence is not proof of non-commit and does not authorize an automatic retry or another transaction. An already saved same-ID selection is recovered without provider work or another INSERT.

Journal reads obtain the root, head, events and small proof envelopes in one SQL snapshot. They verify event and envelope hashes, original candidate/context, proof/event identity and mode, then replay the exact original sequence. They do not fetch every raw historical packet/source blob into a progress response. Selected record reads additionally check the separate source blob's digest, strict source shape and receipt-summary bindings. They retain an original verified observation after a legitimate later remaining-unit change; they do not run today's mutable source predicate or another RPC on historical recovery. This distinction is intentional: envelope/progress recovery is not a fresh provider requalification or a full integrity scan of every separately stored source blob. Corrupt envelopes withhold progress; corrupt source blobs withhold full record recovery.

Generic journal append still refuses caller-supplied finalized labels. The replacement event guard allows only the exact proof-backed finalized or held-unknown event created from its matching immutable record, including its record hash. Existing event identity, byte/count, monotonic time, begin-review expiry and predecessor checks are preserved. A textual reversal check matches all original0124 event conditions after removing only the new operation/count/proof branches. No committed migration was edited;0125 explicitly replaces the trigger and adds the record table/guards. The `= CASE` spacing preserves Wrangler's compound-statement splitting.

All public-facing authority flags remain literal false. Raw source documents and the internal journal return object are not HTTP DTOs. The proof scope remains owned signature/packet/finalized balances, not full historical DEX route/code/custody execution qualification. `applied` describes recorded accounting, not signing permission.
