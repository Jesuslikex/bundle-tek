# Counter Buy settlement preview UI

The existing Counter Buy pricing panel now mounts Codex-owned `counter-buy-simulation.tsx`. A user selects a retained Buy proposal and maximum SOL swap input above, explicitly loads saved verified wallets, selects one, enters a separate positive fee/rent limit and requests a read-only settlement preview. There is no automatic fetch or provider retry. Unverified/watch-only and archived wallets are not offered; proof exclusions must still match the saved plan. The server independently rechecks ownership and the exact saved context.

The summary shows the exact target, simulated swap input, quote input ceiling, network fee, both user limits and expiry. It states that source eligibility, program admission and a separate execution review are still required. No packet bytes, reservation, approval, vault unlock, signing or submission controls are introduced. This is progress toward Counter workflow parity, not a complete executable Counter strategy.

`counter-preview-view.ts` validates runtime response identity, exact selected request terms, all read-only authority flags, target/amount bounds and freshness before rendering. Server modules are type-only imports. Changing the plan, decision, wallet or either limit clears the previous result and aborts pending work. Returning to old values does not restore an old result. A cancelled response cannot overwrite a newer request. Expiry uses a local timer without fetching again. HTML errors use the existing safe JSON reader; rate limits are shown without automatic retry.
