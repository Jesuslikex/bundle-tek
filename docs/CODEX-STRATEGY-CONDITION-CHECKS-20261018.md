# Fresh strategy condition checks, 18 October 2026

## Behavior and remaining authority

Saved strategy review slots now offer an explicit **Check current conditions** action. It reports not-started, DCA-due, ended, or a fresh Limit-market observation. DCA and future-start checks do not read a market provider. A Limit snapshot lists eligible base-token pools and requires the user to select a pool before showing whether its saved USD market-cap threshold is met. There is no automatic pool selection, FDV substitution, quote-token reversal or implicit venue approval.

This adds current evidence to the shared-capacity workflow from `9a6ad9f`. It does not make that capacity a wallet-funds reservation or enable a strategy. Every response retains planningOnly=true and funding/signing/executionAllowed=false. No transaction, quote, packet, signer, approval, job or worker is created. A reported threshold match is not a complete trade-admission decision, a guarantee about provider accuracy, or on-chain pool/program qualification.

The new authenticated POST accepts only an owned project/draft, current capacity revision and held slot ID. The server loads immutable terms itself; client-supplied observations, market outcomes, amounts and authority are refused. It checks active project/draft/wallet revisions before and after IO and binds the result to the same draft/capacity fingerprint. Cancellation after the final context read also refuses publication. The database clock determines the schedule status, so an incorrect application/client wall clock does not shift the captured start.

Snapshots expire after at most 30 seconds, clipped at a pending start or effective deadline. Client expiry uses monotonic elapsed time and charges request latency against that allowance. Results are discarded on context changes, hiding/offline events or cancellation. A late response cannot restore them. Technical time/source/coverage details stay collapsed initially. Slots themselves are unchanged and remain recoverable after a check fails or expires.

## Exact source numbers and bounded reads

The strategy-specific reader keeps the original `marketCap` JSON number text before normal Number rounding, using Node 24's native JSON reviver source context. The current pinned runtime was probed with `1000000000000.000001`: ordinary parsing loses its final micro-dollar, while source capture retains it. The behavior is specified by the [ECMAScript JSON.parse source-context contract](https://tc39.es/ecma262/multipage/structured-data.html#sec-json.parse). The native feature is required; there is no approximate Number fallback when unavailable.

Bounded decimal/scientific source values are normalized and compared to the exact retained six-decimal threshold with integer arithmetic. This preserves distinctions below one micro-dollar and large caps that cannot be converted safely to Number-valued micro-dollars. The normal token-market decoder still validates the source's chain/base mint, pair uniqueness, bounded response and metrics. It still selects at most 20 base-token pools from at most 100 returned records; quote-only appearances are counted and excluded. Existing market/conditional consumers and their formats remain unchanged. Provider receipt freshness does not establish the age of its underlying trades or complete market coverage.

Only the existing fixed public Dexscreener token-pairs endpoint is read. Redirects, oversized bodies and inconsistent responses fail closed. An eight-second server deadline covers transport and body consumption, including ignored aborts; stalled streams are explicitly cancelled. The existing shared per-owner market_read_gates policy permits one provider read per 15 seconds. Failed/cancelled reads do not automatically retry or refund that cooldown. There are no provider credentials, new provider settings or migrations. The only check-time write is this existing read gate; snapshots are ephemeral and are not saved as execution evidence.
