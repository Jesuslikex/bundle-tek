# Owned warmup session review API

20 October 2026. Followsb55c80c. This checkpoint exposes read-only review data; it does not approve or start a session.

POST /api/wallet-workspace/warmup/session-review accepts only a saved plan id and current revision. It requires authentication, an exact same-origin Origin header, application/json and at most2048 streamed UTF-8 bytes. Extra client progress, earlier-revision flags, budgets and approval fields are rejected. Cancelled requests do not receive a usable review. Responses use cache-control:no-store.

The shared loadWalletWarmupProgress service reads the owned plan, retained finalized buy/sell evidence and active approvals in one bounded database batch. Session review adds the active workspace-wallet revision check to that same batch. A changed/archived/missing wallet or archived plan refuses the new review. Every review is rebuilt from current stored data. The existing cycle-progress GET reuses the same receipt/progress/performance checks while preserving archived and historical review behavior; it does not acquire the stricter active-wallet requirement.

Expected domain refusals return controlled409 messages. Missing ownership returns404, stale revision409, and corrupted/storage evidence503 with a generic message. Raw SQL/parser/economics errors are not returned. The successful result contains the finite manifest and a60-second review expiry; this expiry is not a signing authorization. executionAllowed, signingAllowed and automaticExecutionAllowed remainfalse. The exact public context contains no signed packet or wallet secrets. No provider, quote, signing or submission operation is called, and the service issues SELECT statements only.
