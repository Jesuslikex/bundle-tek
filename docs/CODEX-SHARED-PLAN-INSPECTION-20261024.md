# Inspect shared saved plans

24 October2026. Adds useful read-only inspection to the existing mounted SharedProjectsPanel. It does not add contributor/admin roles or wallet-scoped execution.

The existing authenticated shares GET already returns a validated saved project. The new collapsed inspector shows identity, network/venue/quote mint, planning mode, saved timing, planned allocations, supply and selected counts. Holders supply percentages and saved quote amounts use the existing holdersBuyUnit rule; missing quote amounts remain missing, not inferred. Generic creator-tax options and Pump creator-fee/default settings are labelled separately. All amounts are saved plan data, not funding, acquired supply, readiness, profitability or final launch proof.

A strict display decoder admits at most100 exact-shape readOnly:true rows using existing document validation and a bounded1MiB body reader. IDs, metadata and canonical timestamps are checked. The actual project writer in app/api/projects/route.ts strictly advances revisions through Date.toISOString; the client keeps that contract. Historical wallet chain/count mismatch warns without running execution-eligibility validation or blanking otherwise readable history. Invalid envelope/row/document remains a readable page error; unknown historical database formats are not certified.

Display projection omits wallet/fee-recipient addresses, links, clone metadata and artwork URLs. This is NOT transport privacy: the unchanged server response includes saved public wallet assignments, folder/revision references, links and artwork/clone references. The owner disclosure now states that shared scope. Private keys remain outside these project documents. No external image/link is loaded by the inspector and it grants no wallet access.

Member reads share a15-second signal across fetch/body, cancel on supersession/unmount, and use generation/mount guards. Refresh is an explicit GET. Older responses cannot restore a cleared snapshot. Failure clears old data;401 leaves a visible sign-in message and the Refresh control. Unsupported timed-cancellation APIs produce a readable no-fetch message. Initial read dispatch is asynchronous from the mount effect. The summary has a per-token accessible name; changed sanitized snapshot replaces the expanded details. Existing owner invite/revoke and member accept/leave mutation handlers and server authorization are unchanged.
