# Manual owned-token inspection in the seller console

20 October2026. Follow-up to78f8ab0, integrating the785a254 foundation. This is an informational seller inspection, not checkout, asset-transfer approval or sale qualification.

## API

POST `/api/marketplace/operator/token-inspection` authenticates the verified session and configured Bundle operator before any SQL/provider work. It accepts one exact wallet revision and positive SOL asking price, same-origin JSON only, at most2048bytes, with no query selectors or extra caller claims. It uses a separate atomic15-second `marketplace-token-inspection:<SHA256(userID)>` gate in the existing `market_read_gates` table. Ordinary wallet, native inspection and reservation scopes remain unchanged. The pacing gate is the only service persistence; no wallet, proof, listing, hold or order is written.

The real owned SQL reader and token collector run before/after source replay with repeated current session/operator checks, followed by a final access check before the response. Changed seller source returns409, revoked identity/access403, cancellation408 and provider/local throttling429 with Retry-After15. Unknown schema/provider/decoder failures return a sanitized503. There are no retry loops, partial inventories or empty-success fallbacks. Results use no-store. Existing configured RPC, genesis, COption/TLV parsing, per-program minimum floors,32-slot span and60-second expiry remain unchanged.

The client model adds typed stale/ahead-of-device guidance while retaining every freshness predicate. The new panel also checks expiry after asynchronous response admission completes before displaying the snapshot. No current-control, full-asset, extension-semantics, sale, payment, delivery or signing capability is enabled.

## Seller experience

Only a current unpublished listing review mounts the new owned-token panel beside the native SOL check and before draft saving. Both panels have distinct React keys. This distinction was caught by the existing native parent cancellation regression during integration; the final parent tests verify that price changes abort either pending request and remove both panels. Reload, review replacement, cancel and inventory/review expiry keep their original invalidation paths. The native check's copy now states its own SOL-only scope, rather than implying that a separate token check was never performed.

There is no mount/open/pagination/provider request until the user chooses Inspect owned token accounts. A synchronous pending lock, explicit cancellation,15-second local cooldown,429 cooldown reset and ignored late replies mirror the reviewed native flow. Expiry clears rows without polling. Fixed local4xx/503 explanations never display remote parser or provider strings. Invalid result shapes or changed source hashes/selection/counts/capabilities refuse the whole result.

Results separate account count, nonzero raw amounts, frozen accounts, delegates, external close authorities and decoded extensions. Every token account is retained in local20-row pages, with no new request or hidden truncation. Paging clamps bounds and moves keyboard focus to the stable page heading after the new rows commit. Each expandable account shows exact mint/address/program/slot, raw token units, account lamports, delegation/allowance, close authority, native reserve, recognized extensions and encoded-data hash. Mixed mints' raw units are never summed or treated as prices or transferable amounts. An empty provider response explicitly does not prove an empty wallet.

Coverage remains a separate disclosure: both token programs only, with current key control, mint/permanent-delegate policy, confidential amounts, stake/compressed assets/other programs and provenance unverified. Limits are conjunctive: at most200 accounts across both programs,2MiB per enumeration response and16KiB per account; exceeding any one refuses the complete inspection. Large Token-2022 accounts can hit the response-byte bound earlier than the account count. Payment, delivery and signing remain unavailable.
