# Warmup unsigned preparation and recovery UI

21 October 2026. Continues `1a72de7`. The full Proxima parity goal remains open.

The saved-session progress screen now offers **Review next action** only for a due, fresh, unpaused plan. This sends the existing metadata-only `begin-review` command. Client admission verifies the exact selected source action, event UUID, predecessor, version and canonical event hash. Ordinary Pause/Resume/Stop receipts still require null action IDs. A real local SQL journal/projection/client composition covers this transition; the HTTP API and all signing gates are unchanged.

An owned child panel offers a separate, initially unchecked request for an unsigned quote and simulation. It does not authorize signing or spending. Before the one POST, the browser retains and reads back a versioned reminder containing the original ID, consent/hash and complete admitted reviewing journal snapshot (unrequested command receipt removed). The request body contains only the exact preparation API selection and `prepareRequested:true`. Snapshot admission is for display recovery, not a substitute for server ownership, source replay or runtime qualification.

Lost replies, cancellation, changed context, rate limiting and storage failures preserve the original ID. No request retries automatically. Recovery calls GET only; an explicit same-ID retry is possible only after GET reports absence, a new checkbox acknowledgement, the same current head and an unexpired review. A malformed/unreadable reminder blocks new preparation. On reload, only an already-saved reminder triggers a saved-only GET; without one, opening the panel sends no provider request. A source/head change cancels pending publication and clears consent. The original head remains available for historical recovery; a newer journal is never substituted into preparation admission.

The original action/wallet/cycle, expected/minimum output, provider fee estimate, simulated network fee, effective earlier expiry and private packet availability are displayed. Token amounts are explicitly base units because this DTO has no verified token display decimals. Fee values are provisional and non-additive, and native change is not presented as combined SOL spending. Errors use fixed local guidance, never parser/provider HTML. Another browser's colliding preparation ID is retained as guidance only; the client does not invent its missing original review context or adopt it as authorization.

Parent controls and the approval container share the preparation busy state. Controls keep native labels, a separate checkbox, scoped CSS, wrapping layouts and 44px buttons. Automatic Start remains disabled. No vault/password, signing intent, broadcast, timer loop or strategy run was added.
