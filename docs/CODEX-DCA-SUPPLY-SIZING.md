# Captured-supply percentage sizing for Sell DCA

This continuation implements the percentage-unit controls observed in the retained Proxima randomized DCA form. See CODEX-PROXIMA-RANDOM-DCA-LIVE.md. The form establishes percentage controls, not Proxima's supply basis, live rounding, custody or backend execution. Bundle explicitly uses the imported project's saved total mint supply, with its observation time displayed; it does not label that value as live or circulating supply.

Sell DCA now supports Token amounts and % of saved supply for the total budget and randomized per-cycle bounds. Positive percentages up to 100 with at most six decimals use exact BigInt arithmetic. The total and maximum bound round down to token atoms, while the minimum rounds up. Dust totals and bounds containing no valid token-atom amount are rejected. Exact cycle inputs remain fixed after generation/save; changing the unit clears previous numeric inputs, and changes to the captured supply invalidate a randomized preview. Buy remains an exact SOL-input workflow.

New optional dca-supply-percentage-v1 metadata retains mint, total supply, observed time and canonical requested percentages. The server verifies it against the owned saved project, recomputes total/bounds and compares the exact cycle inputs and independently declared random budget. Forged supply or modified percentage amounts cannot be saved. Immutable session capture hashes include the metadata. Legacy token/SOL sessions retain their previous terms.

Preparation, approval and submission verify the captured supply against the current owned project/revision. Their final SQL guard also binds the complete project document, rejecting concurrent changes even when the supply fields themselves are unchanged. This does not reread chain supply or silently recalculate a signed packet. A refreshed/changed project requires a new session; existing signature registration and receipt recovery remain available. Saved session history shows the original percentage intent and observation time.
