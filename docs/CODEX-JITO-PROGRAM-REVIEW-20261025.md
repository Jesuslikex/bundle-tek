# Jupiter and Token-2022 provenance review

25 October 2026. This is a bounded provenance/policy proposal, not a complete security audit or live qualification. No application pin is changed. Claude retains the stock pin file and proposed review PR.

## Token-2022: official release bytes matched

The complete retained code from the 15:01 UTC read-only sample is 1,382,016 bytes, full SHA256 `15a2e615a42e20f31714bbaaee43002ae6f1cda2e8d7118243117ab3c1342e2d`. Extraction rechecks original raw request/response hashes and IDs, exact account positions/floors, stable program links and 45-byte deployment headers, complete contiguous code slices and the already-observed code hash. The 45-byte header is excluded from this code hash. This is a chunked provider observation, not an atomic snapshot; unchanged headers cannot exclude same-slot code rewriting.

The [official Token-2022 v11.1.0 release](https://github.com/solana-program/token-2022/releases/tag/program@v11.1.0) identifies source commit `8867f751c0f69367ba03af4f85510b5611989491`. Its downloaded 611,056-byte artifact has SHA256 `3dde54d202caa2d10514fd58a154df5f26f07643f9f5fd0402ff08084f0cb954`, matching GitHub's published asset digest. The retained code's first 611,056 bytes equal that artifact byte for byte; all remaining 770,960 bytes are zero.

The verifier's [pinned hash implementation](https://github.com/solana-foundation/solana-verifiable-build/blob/26ba8211eddbfab49d30826d15a2408332b89543/src/main.rs#L768) removes trailing zeros before hashing. The official artifact has 15 trailing zeros; the retained code has 770,975. Both therefore have the same 611,041-byte normalized content and hash `5e888b294bd1941bfc47107a73d5e40bb24fde0d639f69099e7920ad8b6413d9`. That also matches the [public verification record](https://verify.osec.io/status/TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb), retrieved 15:27 UTC, which reports the same source commit and last verification 23 October. The API response is a third-party attestation, not an independently reproduced build on this PC.

**The candidate application pin remains the full padded-code hash `15a2e615...`, never the normalized hash.** No application hash normalization, loader/authority acceptance or scan rule is changed. The observed deployment slot is 460497271; authority remains `AeLmXCbPaQHGWRLr2saFsEVfmMNuKnxRAbWCT9P5twgz`.

The release links a [Zellic assessment](https://github.com/anza-xyz/security-audits/blob/master/spl/ZellicToken2022Audit-2026-09-24.pdf). Its scope pages 9–10 describe five specific PR diffs: scaled UI amounts, account-length helpers, Memo Transfer, CPI Guard and TLV resolution. It reports no findings in that scope. This is not a whole-release 8867f75 audit or proof of every dependency. Scope pages 9–10 and finding-count page 6 were visually checked. No claim that all release code was independently audited or reproduced here is made; Docker and solana-verify are unavailable in the checked Windows/WSL paths, and none was installed.

The retained router code remains 2,892,224 bytes and SHA256 `0394bfa4311fac40dd3d32e431ab2f541227e6c32923715455cfac58e4004d30`. Removing 855,847 trailing zeros produces 2,036,377 bytes and normalized SHA256 `5e31d320f5d88ae93c7983ce82a1497067abd86ff540b35073abaeeb25ef397b`. This does not match an independently established source/build artifact in this review.

The [public verification endpoint](https://verify.osec.io/status/JUP6LkbZbjS1jKKwapdHNy74zcZ3tLUZoi5QNyVTaV4) reported unverified with no source commit or executable hash. This service result is not proof that Jupiter is unsafe or that no verification exists elsewhere.

Jupiter's [official audit index](https://developers.jup.ag/docs/resources/audits) links the October 2025 [Offside Labs v6 report](https://github.com/jup-ag/docs/blob/main/static/files/audits/swap-v6-offside-october-2025.pdf). Its scope names commit `41d454b84058a9680441b779eb46dc2a00f7d4f1`, with remediation commits `20af53e33ef128b54f2c4cb48ecd04a033124cca` and `87fc19c2949282eae8c5baa021cb81f8a2bc7086`. The report records two high and one medium issue as fixed, and a Memo/Token-2022 compatibility observation as acknowledged. It supplies no mapping to today's observed code hash. The referenced aggregator repository returned 404 through the public GitHub API; this can mean absent or inaccessible, not necessarily nonexistent. The public [CPI repository](https://github.com/jup-ag/jupiter-cpi) contains IDL-generated client bindings, not proof of router implementation equivalence.

Existing REA/Ghidra evidence already records unsupported SBF architecture for this router. This review did not repeat the same unavailable engine call, install a replacement or claim decompiled semantics. No Jupiter pin proposal is supplied. Re-pinning solely from current provider bytes would not close this identified review gap.
