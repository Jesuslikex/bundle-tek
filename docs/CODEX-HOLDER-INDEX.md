# Mint holder enumeration

The token workspace now includes a separate mint holder index panel. Claude's sampled-holder view, watch parent/helper and tests remain untouched. Integration is in `components/imported-token-projects.tsx`; implementation is in the new holder-index panel, pure accumulation helper, provider adapter, and authenticated `/api/imported-projects/holder-index` route. `balanceRpc` now accepts named JSON-RPC parameters as well as arrays, retaining its lossless numeric decoding and response bounds.

Provider contract: [Helius getTokenAccounts](https://www.helius.dev/docs/api-reference/das/gettokenaccounts). Requests use mint, page, limit 1000 and `options.showZeroBalance=false`, through the existing server-only indexer RPC. Each request validates mainnet genesis, mint supply, account identities, raw u64 balances and indexed slot metadata. Provider errors are sanitized. No credential configuration was changed or displayed.

The API binds reads to the signed-in owner's active saved Solana project and expected revision, rechecking that project after the provider call. The browser combines token accounts by owner with BigInt amounts, rejects duplicate/overlapping accounts and changed supply/precision, and commits validated pages atomically to its accumulation. Pages are sequential, paced by one second, cancellable, and stop on hiding/offline. Partial results can be resumed after stopping or errors; restarting clears them. A 500-page/500,000-account resource limit is explicitly partial. Enumeration is exhausted only after an empty page, not merely a short page.

The UI shows scanned accounts and positive-balance owners, supply coverage and unreconciled remainder, top 10 scanned concentration, top 20 scanned owners, indexed slot range, observation interval, provider hostname, and an Open token chart handoff. It does not infer team/pool ownership, claim an atomic snapshot, or advertise exhausted provider pagination as proof of global chain completeness. Runs and validated pages are now persisted in D1. Reload restores saved pages without starting enumeration. See `docs/CODEX-HOLDER-INDEX-PERSISTENCE.md` for the persistence follow-up.
