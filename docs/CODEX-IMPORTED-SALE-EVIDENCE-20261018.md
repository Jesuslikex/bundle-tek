# Retained sale receipt evidence, 18 October 2026

Recorded launch buys cannot safely enter sale accounting using only a parsed sale summary. This checkpoint adds a server-internal retained sale source that can replay the original signed packet and finalized balance metadata. It does not yet assign launch units to sales or calculate profit.

The source must be an owned finalized imported Sell with its exact original preparation, approval, project/wallet revisions and shared signature registration. Buy or malformed sources refuse before empty-history publication or a capture throttle write. Capture performs only mainnet genesis and finalized base64 transaction reads. The original exact-signature verifier and receipt decoder verify the packet, lookup addresses, token units, fees, native/rent settlement and retained summary. SPL and supported Token-2022 historical sources use the same original parsers. Expired signing deadlines do not invalidate historical replay or authorize a new signature.

Only required transaction/balance metadata is retained; logs and provider extras are excluded. Captured values are detached before asynchronous verification. Envelope and parent hashes bind the original documents. Raw metadata is capped at 1 MiB, the evidence envelope at 1.25 MiB and the parent at 512 KiB, keeping the combined record below 2 MiB. Individual original documents allow up to 64 KiB UTF-8, including the original 16,384-character approval/receipt limits. Provider mainnet/finality and metadata remain trusted observations; this is not independent block inclusion, venue program/economics or acquisition-basis verification.

Append-only migration `0115_imported_sale_receipt_evidence` adds owner/receipt and owner/signature uniqueness, a 4,000-record owner cap and eleven guards. Insertion compares captured parent documents with the exact current source rows. Saved evidence and its referenced receipt, preparation, approval identity and signature registration are immutable. An unrelated approval timestamp can still change. Capture retries recover the same saved receipt without RPC; a lost committed response is replayed before success. Cancellation after commit leaves saved history recoverable. Changed parents, missing guards and corrupt evidence refuse publication. Saved reads perform no RPC, provider setup or mutation. Public summaries omit packet bytes; the exact accounting source is private to server callers.
