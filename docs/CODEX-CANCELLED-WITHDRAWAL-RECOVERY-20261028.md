# Cancelled withdrawal packet recovery

A second session can cancel a withdrawal while a wallet prompt remains open elsewhere. Cancellation alone does not prove that the wallet did not return a signature. A user can now explicitly inspect a cancelled history row for the exact signed packet retained in this tab. Recovery requires the current signed-in owner, exact wallet and funding scope, a fresh authenticated exact-record read, and cryptographic verification of the packet against that record. It displays a warning and a private copyable packet only; it does not register, sign or submit anything, or replace another active withdrawal.

The server compares a client-provided owner context marker with the authenticated user before the exact owner/wallet/funding lookup. The marker is not authentication. Existing unscoped pagination remains compatible. The client clears or fences displayed recovery as it observes session and context changes, and can verify a same-owner in-memory fallback if session storage cannot be read.

Independent synthetic verification passed 44 tests in six focused files; the final edited owner-scope test was repeated with six passing tests. A separate clean-dependency worktree ran the existing local D1 withdrawal route and owner-scope tests: 29 passed with no skips, and the route source matched the active checkout. Its owner-scope test was then refreshed and its current six tests passed. TypeScript, typed lint and formatting passed; independent source review found no additional blocker. The old dependency checkout could not start its own workerd instance and did not complete the database test.

Limits: a cookie/session change after the last authenticated check is not atomic with display. Browser session storage is per tab and can be lost on closure, eviction or storage failure; a failed write after unmount can still lose the packet. The path does not prove whether a transaction landed or authorize another attempt. No hosted database, provider, real wallet, signature, broadcast, funded action or deployment was used.
