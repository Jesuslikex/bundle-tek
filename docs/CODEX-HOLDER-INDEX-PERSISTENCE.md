# Durable holder runs

Holder scans now save each validated provider page to D1, scoped to the signed-in owner, saved project, project revision and UUID run identity. The workspace loads the latest run on opening, supports selecting prior runs, and restores pages through bounded GET pagination. Opening or reloading never starts a holder-index provider scan.

Schema: `db/holder-index-schema.ts` is exported by the existing schema. Drizzle generated `0067_petite_venus.sql` and its matching snapshot/journal entry, containing only `holder_index_runs`, `holder_index_pages`, `holder_index_accounts` and the recent-run index. Migration was applied to the existing **local** D1 database with Wrangler `--local`. No remote migration or deployment occurred.

The page record is a transactional commit gate. Account-address uniqueness rejects overlapping pages and rolls back the entire batch; exact raw amounts are accumulated as BigInt in application code and persisted as decimal strings. Conditional inserts/upserts recheck the current active Solana project revision and preceding run page. Already saved pages are returned idempotently without a new provider read, allowing recovery when a response was lost after committing.

Stored partial runs may be explicitly resumed only within five minutes of their latest saved page and only on their original project revision. Supply/precision/provider changes reject extension. Older runs stay readable and require starting a fresh scan for current data. This guard limits mixing old and new enumerations; it does not prove an atomic snapshot. Each project can retain 20 runs, each capped at 500 pages. The selected run can be explicitly removed through a disclosed deletion control and owner/revision-guarded DELETE. No saved run was automatically removed.

Live QA on 2026-10-12: a BONK run saved 1,000 accounts / 996 positive owners, survived a full browser reload and project reopen with no running scan, then explicit Resume appended another page to that same run. Reload saved history restored 2,000 accounts / 1,992 positive owners. Coverage was 0.0453% of reference supply, still partial. Index slots 455903681 to 455903966; observed interval 04:48:04 to 04:49:06 London time. Stop was used after each read. This is a new persistent QA run; the earlier 18,000-account exploratory run was not retroactively persisted.

Validation: 28 focused tests passed across six files. Real SQLite tests run the generated migration and actual batch SQL, checking exact totals, owner isolation, overlapping-page rollback, stale concurrent writes, project invalidation, expiry, and scoped removal. Client history tests check restore pagination, missing/foreign pages and loop rejection without POSTs. Existing route/provider/rendering and wallet-balance tests also passed. TypeScript, scoped lint and production build passed with existing build warnings. The deletion action was tested with isolated SQLite data, not clicked against the retained live QA run.

The phone saved-run selector fits without document overflow (375px client/scroll width at the 390px viewport). Proof artifacts: Codex chat `outputs/holder-index-saved-desktop.jpg` and `outputs/holder-index-saved-mobile.jpg`. Claude's watch-wallet parent, holder view, helper and tests retain their original timestamps and were not edited.

Still unverified: full provider exhaustion on a live suitable mint, global chain coverage, atomic/fresh holder positions, reconciliation of an exhausted index against finalized supply, cursor pagination behavior, and integration of these indexed owners into Claude's watch workflow. The existing page-based enumeration and five-minute resume guard are explicitly limited. No keys, signatures, broadcasts, paid upgrades, or remote publication were involved.
