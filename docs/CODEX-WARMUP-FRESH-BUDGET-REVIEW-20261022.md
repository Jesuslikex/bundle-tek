# Owned warmup execution budget proposal

22 October 2026. Source base `7b05e8b6d7d582a7f5d5b2c2e9dfba742b0104cc`. This adds an internal source-derived review dependency; it is not a mounted review UI, API, approval, root publication, reservation or running Generate Activity session.

## Complete proposal from current owned facts

`reviewWarmupExecutionBudget` takes an authenticated owner, exact retained review selector, proposed distinct root/consent identities, session deadline and one gross fee/rent ceiling for every action in its exact original order. The request is strict and detached before any await. It accepts no mint metadata, provider URL, evidence hash, approval, verified flag or altered buy amount. The service reads the actual owned source, invokes the existing current asset collector internally and checks the source snapshot again after building the terms.

Every pending action is retained, including sells of previously recorded lots. Current program and decimals come from the actual mint evidence. Saved-lot units and their original receipt-row hashes come from the retained source; missing or mismatching program/units refuse through the existing source/asset checks. Only wallets appearing in actions enter the intent, while the complete original plan/wallet source remains bound by `sourceSnapshotSha256`. This snapshot digest is deliberately the intent's `sourceSha256`; it is distinct from the retained raw-source digest. Wallet buy limits exactly equal the saved review's current buy spend, and independent fee/rent ceilings are summed with bigint, with the existing u64 checks intact.

## New limits, separate from historical net reserve

The saved review subtracts fees plus positive historical net rent. This service does not call that gross historical cost or reuse it as a new allowance. Its budget binds the saved plan reserve, saved review net remaining reserve, old maximum native spend, historical recorded fees/net rent and the exact signed difference between old and newly proposed limits. Historical gross fee/rent remains explicitly `not-established`. A new proposed ceiling may exceed the old reserve; that is a different limit requiring separate human approval, not permission granted by the old review. No new approval is verified here, and no wallet funding sufficiency is asserted.

The named setup-allowance policy requires each action ceiling to cover the current Rent minimum for one target token account plus one classic WSOL token account. Token-2022 uses the existing170-byte account size. This is a conservative planning allowance even when an account already exists. It is not a claim that either account is missing, a total fee/setup quote, a new rent formula or support for arbitrary route accounts. Extra route setup and network fees still need exact per-action qualification inside the proposed ceiling. Refunds and proceeds never replenish limits. `feeAndSetupCoverageVerified` stays false.

The proposal binds its budget and current assets into the verifier-evidence domain, then binds complete existing execution terms. Those digests prove neither human consent nor funds. Returned budget and verifier copies are detached. The proposed root/consent IDs have not been published or admitted for uniqueness. The requested session deadline remains a proposal and the model's five-minute tail bound still applies. The retained review's original timestamps/expiry remain unchanged, and the earlier asset expiry is also exposed as `proposalExpiresAt`. Final source, asset-time and minimum-pacing checks occur after all hashing; cancellation retains the parent reason.
