# Durable Auto Sell configurations

25 October 2026. Source base `e9a210c`. Auto Sell can now save immutable named configuration versions, inspect historical settings and explicitly restore a stopped draft for a new reviewed run. This closes configuration loss on reload; it does not establish durable automation or resume prior session accounting.

## Complete configuration flow

The new profile codec reuses existing strategy/session validation while admitting only the known data fields first. It retains Counter, fixed/randomized DCA, Limit Orders, delay/duration, supply or token limits, slippage, ignored-wallet settings and ordered selected-wallet revisions. It excludes vault/password data, approvals, runtime counters, processed targets, locks, signed bytes and recovery reminders. All stored/returned signing, execution and automatic-resume flags are false.

Each save has an exact request ID, stable profile ID, expected prior version and canonical terms digest. Insertion rechecks the owned imported token project/document, mint/units and current wallet revisions atomically. Concurrent versions refuse rather than overwrite. Exact retries recover the original version before checking whether current sources changed. History uses 20-row scalar metadata pages; opening a version separately fetches and verifies its full canonical terms. No full-document aggregate page exceeds the client response budget.

The UI loads history only on request. Restoration has a separate initially unchecked review, compares current token identity/units, discloses captured/current project revisions, clears changed wallet selections and clears the password and draft edit approval. It invokes the existing configuration loader, never Start, unlock, execution or resume. Original cancellation guards, saved outcomes and pending-operation accounting remain. New Run still requires the existing fresh password/action and server checks.

Invalid visible duration/session/strategy fields block saving instead of silently saving a normalized zero. History and restoration remain usable to replace an invalid draft. Raw duration changes also invalidate the saved review. Missing saved slippage explicitly discloses the existing default before restoration.

Expired authentication offers a separate-tab sign-in link and requires an explicit manual retry, preserving the current draft. Unknown saves retain an original-ID reminder before POST; exact GET reconciles it without retrying the write. The reminder contains only identifiers/version/digest. If browser storage is blocked, the UI warns that the reminder is memory-only; history can still locate a save after remount. Dismissal affects only that local reminder, never server data. Editing context can abort a pending save, which may nevertheless commit; it is not declared failed from that interruption.

Capacity is explicit: 100 profile groups and 1,000 retained versions per owned token project, up to 500 selected wallets and 1,024 ignored addresses per strategy, 262144 UTF-8 bytes per terms document. Large configurations refuse without truncation. Historical versions cannot be edited or deleted; archive/retention management is not introduced here.
