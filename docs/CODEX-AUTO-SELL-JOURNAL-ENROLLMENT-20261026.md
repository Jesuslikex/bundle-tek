# Explicit Auto Sell journal recording and uncertain-save recovery

26 October 2026. Source base `10493bf`.

Saved Auto Sell configurations now offer **Record a saved run journal**. The user explicitly fetches the exact owned configuration again, reviews it, ticks a separate unchecked approval and records metadata through the unchanged original create API. Recording fixes original server clocks and captures owned-wallet exclusions; it does not connect the tab-only runner, prepare orders, unlock a vault, trade, resume or restore counters. Restore-settings approval is separate and cannot authorize recording.

## Recovery and cancellation

Before POST, the client persists and reads back an owner/project-scoped metadata reminder under an exclusive browser WebLock. It contains only opaque owner scope, project/run/version IDs and configuration hash. A one-use in-memory review is bound to that exact version and new/retry mode. A retry preserves the captured original run ID and requires fresh explicit review. Existing uncertain reminders prevent replacement IDs. Cancellation, timeout, missing/malformed/HTML responses and 404 never clear an uncertain request. No retry is automatic.

Explicit recovery checks for a terminal recording-stop receipt first, then reads the original run only when the first API positively reports no stop. An existing original run without a stop is strictly checked before that typed fallback. Exact verified run/receipt alone permits matching local-reminder cleanup under the same lock. Busy/missing locks, changed storage or failed clearing retain the reminder and give manual same-ID recovery. Account, pending identity, project/token/revision, saved-version and disabled context changes abort and clear local review/consent. Disclosure close aborts waiting. There are no automatic server reads on mount, open or reload.

An uncertain create can become unretryable after project changes. New additive source migration **0155_auto_sell_run_record_stops** solves this with an immutable original-request terminal fence and a separate authenticated API. A second unchecked approval stops only that metadata request. If its run already exists, the original run, head, clocks, attempts, Stop state and all held allowance remain untouched. If no run exists, an immutable receipt prevents any delayed INSERT for that owned run ID, including a changed configuration. The missing-run fence consumes no run slot. Atomic create/fence ordering and exact same-ID replay select one original result, including lost replies. There is no local dismiss or 404 reset.

The new endpoint checks nine uncached schema fingerprints; its capability is explicitly verified before any UI create dispatch. Missing0155 refuses before storing a new reminder or sending create. Stop recovery is saved-only, owner-scoped and valid after source changes/archive. Same-origin POST requires exact bounded JSON and explicit consent; every response keeps signing/execution/automatic-resume false. The terminal receipt is not a run Stop or release/financial authorization. Raw user IDs and credentials are not returned or stored by the client.
