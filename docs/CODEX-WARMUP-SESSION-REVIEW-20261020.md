# Automatic warmup session review foundation

20 October 2026. Follows5dc9aef. This is a pure internal planning module, not an API, running session or signing authorization.

reviewWalletWarmupSession rebuilds a finite review from an active saved Solana plan, its current-revision cycle progress and validated recorded lot economics. It uses the existing saved amount matrix and plan builder. Range amounts are never rerolled. Each selected wallet retains its captured revision. Completed recorded loops produce no new action; partial loops produce only sells tied to the exact remaining saved buy lots. A future buy's sell depends on that buy action and cannot be assigned fabricated acquired units.

Past schedules are rebuilt from the review time while preserving the saved delay/stagger. Original and effective starts are both included in the exact review context, so missed times do not become a catch-up burst. A future saved start remains unchanged. Future scheduling must still recheck due times and serialize rate-gated work; this module does not start timers.

The review shows each wallet's remaining planned buy inputs, original fee reserve, recorded buy spending, network fees, net rent change, remaining reserve and maximum further native spending. Recorded fees and positive net rent reduce the reserve. Negative rent does not increase the original reserve or reimburse paid fees. Recorded buys plus proposed buys cannot exceed that wallet's original saved buy budget; duplicate historical buying or exhausted reserves require manual review. Completed wallets receive no new spending allowance. These are recorded-cost bounds, not proof of balances or sufficient future fees. Failed/external costs remain outside the existing successful-receipt evidence and need runtime checks.

The module refuses active approvals, excluded receipt history, earlier-revision inclusion, stale/mismatched progress, changed saved totals, bad wallet captures and archived/non-Solana plans. It owns nested returned values. contextKey retains exact public review context; it is a JSON binding, not a cryptographic capability or authentication token. Every result has executionAllowed, signingAllowed and automaticExecutionAllowed set tofalse.
