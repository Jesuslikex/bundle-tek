# Marketplace range filters

Local read-only marketplace follow-up, coordinated with the other Bundle chat. Adds optional maximum funding age, maximum SOL balance and minimum/maximum transaction counts to the existing catalog selector and authenticated route schema. Amount inputs now use SOL in the UI, converted exactly to integer lamports with no rounding or floating-point conversion. Maximum values cannot be below their minimums. Original provider identity, freshness, coverage, cheapest-first selection, spacing and checkout-disabled constraints remain.

Advanced filters are collapsed by default. Reset aborts pending reads, clears stale inventory and restores the original inputs without a fetch. Editing any filter invalidates displayed results. Responses must echo exactly the requested parsed filters. No region selector is fabricated because the supplier schema has no verified region field. Purchase, folder delivery, wallet import and order history are still unavailable; this is catalog work only.

Validation: 35 tests across marketplace-catalog, marketplace-provider, marketplace-panel and the actual catalog route. Covers inclusive age/balance/transaction bounds, inverted ranges rejected before provider access, malformed amounts without exceptions, exact values beyond Number safe integer, nine-decimal SOL, u64 bounds, response-filter mismatch and reset. Scoped typed lint passes; TypeScript passed with the same five feature files before the added route-only test. Final TypeScript is run with the subsequent warmup checkpoint.

It uses fixed public fixtures, never a connected supplier or wallet. Verified collapsed/expanded filters, invalid SOL/ranges, exact three-row selection and totals, and Reset clearing results/inputs.
