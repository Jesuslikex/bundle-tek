# Clock wire and writable-state diagnosis instrumentation

This checkpoint records diagnostic changes before further live observations. Earlier generic writable refusals did not retain their exact account/phase operands and cannot be reconstructed retroactively.

The writable guard's predicate, owner set and public error remain unchanged. Private, non-enumerable metadata now captures address, actual owner, exact raw lamports, captured data length, phase and actual account-read/simulation context slot. Comparisons retain the permitted executable/blocked-owner/system-data predicates alongside observed values. When an earlier inventory/snapshot exists, its owner/executable/lamports are compared with the rejected state; otherwise the prior value is explicitly unavailable or absent. Inventory reads still request the same slices and full later protected-state reads remain intact. Tests verify both before-inventory and simulated-post-state diagnostics survive the public 409 without exposing the account through JSON serialization. No owner/program is newly permitted.

The unsigned harness observes bounded clones of only responses whose getMultipleAccounts request includes Clock. It records the raw provider RPC context, Clock slot, chain timestamp, request id/floor/commitment, server receive time and SHA256 of the exact forty Clock bytes. It also records the transport-decoded Clock hash/context independently, for correlation. The observer adds no RPC and never changes the original response, retries, rebases a slot or grants acceptance. Malformed/unavailable observation is labelled unavailable. Copying is bounded at 2 MiB; diagnostic time is recorded and remains inside qualification timing. The production transport retains all batch mapping, size, floor and cancellation checks.

The existing exact Clock/context equality and 30000-ms wall-time bound remain unchanged. Solana's [RPC method contract](https://solana.com/docs/rpc/http/getmultipleaccounts) supports commitment and minContextSlot, while an [Agave maintainer discussion](https://github.com/anza-xyz/agave/issues/4807) explains that response context alone is not an atomic historical-account guarantee. This corroborates the kind of mismatch observed historically, but does not prove the implementation fault behind this endpoint. New raw-provider evidence will distinguish a mismatch arriving on the wire from a Bundle transport transformation. Even equality is not advertised as proof of immutable historical state. No tolerance change is proposed.

Targeted verification before live capture: five files / sixty Vitest tests and four bounded-clone Node tests pass; plain TypeScript and scoped lint are checked separately. Original predicates, 32-slot and minimum-output rules, both fresh code observations, group serial defaults and stock signing gate remain intact. No Claude UI, provider/credential/cron change, remote SQL, push/deploy or real wallet action. Use the existing pinned references for one fixed alternating six-attempt sample, retain every refusal and record source/receipt hashes in a separate evidence commit.
