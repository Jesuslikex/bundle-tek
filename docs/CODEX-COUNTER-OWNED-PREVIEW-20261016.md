# Owned read-only Counter Buy preview

This checkpoint joins the existing Counter target/preparation, original-packet simulation and gross native settlement libraries behind an owned server boundary and POST /api/imported-projects/counter-previews. It advances the existing Proxima-style Counter workflow beyond quote-only pricing. It does not complete Counter execution or signing and is not yet wired into the visible controls.

The request has exact project, plan, retained decision and wallet identities/revisions plus canonical raw SOL-input and fee/rent limits. Client authority flags and unknown keys are rejected. Before any provider stage, an owner-scoped SQL join requires an active matching Counter plan/project, an unarchived eligible saved Solana wallet with ownership proof, and all currently proven owned wallets in the plan's exclusions. The decoded ledger, recorded proposal, project bytes, mint and precision must match. A watch-only recipient record without proof cannot reach provider preparation. Both request budgets are exact u64 strings; the input limit must be positive.

Preparation receives only the owned plan/proposal, selected wallet and input budget. Its returned ExactOut target, direction, wallet, project/plan identities, decimals and quote ceiling must match the request and retained decision. The existing collector simulates the actual unsigned packet with the fee/rent limit, and the existing settlement library independently checks its native gross spending/wrapping/rent behavior. The owned snapshot is re-read after preparation, simulation and settlement; pauses, archive/revision/ownership/exclusion changes refuse the preview. Cancellation/expiry also refuse publication. Provider failures are sanitized, without propagating URLs or secrets.

The API requires authentication, same-origin JSON, an exact bounded body and the existing per-owner15-second provider gate. It writes only that quota record; it does not mutate the plan, consume a proposal, retain a packet or create a reservation/approval/signing intent. The response has no-store caching and returns the public amount/cost/expiry/hash summary, not transaction bytes, provider request material or internal snapshots. It explicitly retains sourceRevalidated=false, programCodeAttested=false, reservationCreated=false, approvalAllowed=false, signingAllowed=false and executionAllowed=false. A preview cannot be supplied as an approval token. A new future durable review will need its own authoritative admission and fresh packet.
