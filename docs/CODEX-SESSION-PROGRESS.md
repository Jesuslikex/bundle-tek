# Receipt-backed session progress

13 October 2026. The existing saved-wallet outcomes panel now summarizes cycle/entry progress and exact saved input allocation across its loaded snapshot. It uses the existing authenticated outcomes API; opening the summary creates no additional provider request, preparation, signing or submission. Both DCA cycles and other saved session entries are supported.

Only entries with matching finalized receipt evidence contribute to the verified allocation. Exact BigInt sums conserve the saved budget; the weighted allocation percentage is floored to basis points. Awaiting signatures, signed/submitted approvals, finalized approvals without matching receipts, failed/cancelled approvals, absent retained approvals and unavailable approval sources remain separate counts. Missing sources are unknown rather than successful or unused. Duplicate verified receipt IDs/signatures and contradictory identities prevent aggregate reconciliation. Individual recovery details remain available below the summary.

The label deliberately describes **input allocated to receipt-verified entries**, not all-in spend. In particular, Buy allocation is its saved SOL input budget, not an independent chain-wide spend reconciliation. Network fees, reserves, all wallet turnover, available balances and P&L are not derived here. Unverified allocations may already have been submitted or settled, and absence of a retained record does not prove no attempt. The existing sampled-time and incomplete-source disclosures remain visible.
