# Immutable operator listing drafts and recovery

20 October 2026. Baseline `07f9d89`. Bundle remains the sole intended seller. This connects the existing exact unsigned listing review to private draft saving and same-ID recovery. It does not publish inventory or implement checkout.

## Save and recover

New `/api/marketplace/operator/drafts` GET/POST authenticates and enforces the existing server operator allowlist before storage. No real allowlist was configured. POST requires same origin, bounded 2 KiB JSON and the exact explicit acknowledgement: "Save this exact unpublished draft. This does not publish a listing, accept payment or authorize key delivery." It accepts only a lowercase UUID, selection, original review time, selection/evidence hashes and acknowledgement. Client-supplied owner, role, evidence, keys or authority are not accepted.

Before an initial insert, the service reads the operator's current owned inventory again and reconstructs the review at its original time. Price, current wallet revision, retained control/history evidence and receipt counts must match the exact reviewed hashes. Only derived activity age is rebased to the original review time; history/proof timestamps are unchanged. Both review generation and save enforce the existing 60-second review lifetime. Reusing an ID with different contents is refused. Identical retry of an already saved ID recovers the original record after expiry or archival without another insert. A duplicate snapshot under another ID is refused.

Migration `0118_marketplace_operator_drafts` adds immutable owner-scoped storage, per-owner review-hash uniqueness, a history index, an insertion guard and update/delete refusal. The guard binds row/document wallet, revision, review hash and timestamps, checks positive exact u64 lamport pricing, requires the exact acknowledgement/custody disclosure, retains all literal false authority flags and checks the active owned wallet's label/revision/update timestamp at insertion. Historical evidence is a previously validated read snapshot, not an atomic latest-chain or latest-receipt assertion. The save does not reserve or freeze that wallet, or certify sale readiness. No signing payloads or private key material are stored.

Stored public evidence is bounded to 16 KiB. GET verifies row bindings, chronology, strict schemas, exact review replay and its SHA-256 digest. It uses the original capture time, so old drafts remain historical and never become fresh approvals. Missing schema/guards or damaged records fail closed with sanitized errors. The schema has no publishing, purchase or delivery state transition.

## UI behavior

The separate owned draft panel is mounted in the existing owned seller console. It has an initially unchecked acknowledgement for each review, an explicit Save unpublished draft action and manual ID recovery. A recovery reminder containing only the public exact save selection is persisted in session storage before POST. If that reminder cannot be written, nothing is sent.

An unknown save keeps its original ID, blocks another save and never retries automatically. Stop waiting, context edits and unmount abort local waiting but preserve the recovery reminder. Late responses are discarded. Reopening restores the ID without automatically fetching or writing. Recovery uses only GET and checks the exact original request when a reminder exists. Only resolving that original ID or receiving its 404 permits clearing the reminder; an unrelated ID's 404 cannot clear it. Clearing the reminder deletes no server record. A successfully retained review cannot be saved again by checking its acknowledgement again.

Recovered details show asking price, wallet, save/capture times, custody disclosure and review hash, explicitly marked not published. Natural review/inventory expiry clears the fresh review while retaining recovered historical details. There is no Publish, Buy, payment or Sign action. Protected shell/token layout files and provider/credential/cron settings are untouched.
