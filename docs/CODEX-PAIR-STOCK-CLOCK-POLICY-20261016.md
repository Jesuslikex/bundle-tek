# Approved stock-only Clock evidence policy

The user approved exact equality or exactly +1 for stock-pair runtime evidence only. createStockPairEvidenceRpc is a server-owned, per-lifecycle wrapper used by the order-first stock path and its unsigned qualification harness. It retains the original response context; accepted Clock metadata records contextSlot, clockSlot, effective slot, relation equal/+1, and timestamp. It raises subsequent ordinary/code request floors to the later Clock slot and validates returned contextual reads against the actual raised floor. No request flag can enable this policy.

The wrapper requests a second actual Clock in the same getMultipleAccounts response. Both canonical 40-byte accounts must agree exactly, including their account envelopes. Compatible-request coalescing now excludes any request with duplicate keys, so the transport cannot deduplicate these observations and manufacture agreement. JSON-RPC batching, byte caps, child floor/response mapping validation, pacing and concurrency remain unchanged. The wrapper removes only its own appended duplicate before publishing the caller's original account positions, and binds the validated Clock metadata to that exact response object with an internal WeakMap. Evidence readers recover the effective later slot without rewriting response context or packet bytes.

The original pairClockUnixTimestamp and every unwrapped reader still require exact equality. Group signing source, Clock policy and serial code defaults are untouched. Stock +2 or behind, invalid owner/executable/encoding/size/timestamp, more than 30 seconds skew, disagreeing duplicates and any effective span above 32 are refused. Genesis/network and all custody/code/lifetime checks still run. The explicit stock scope records each accepted observation in owned stored evidence and the unsigned diagnostic receipt, including samples that later fail.
