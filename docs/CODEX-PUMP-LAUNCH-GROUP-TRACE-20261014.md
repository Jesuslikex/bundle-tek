# Sequential launch-group trace checkpoint

14 October 2026, based on aef5267. Adds a read-only one-call bundle trace collector and retained-trace verifier. This is a mandatory continuity/resource/source gate, not complete group economic simulation or an enabled launch API.

## Implemented

The gate reconstructs all unsigned packets and validates manifest/allowance hashes, exact packet fee indices, full holder limits and funding bank ranges. Groups over five packets reject before any provider request rather than falling back to independent simulations or submitting a subset. Tracked account configurations cover the complete packet union and known public configuration accounts; non-transaction configuration accounts are assigned to a frame with room within the 64-account observation profile.

The collector uses an explicitly supplied provider and sends exactly one simulateBundle request: ordered original base64 packets, the selected funding bank slot, signature verification skipped, original blockhash preserved, and complete per-frame pre/post account configurations. It never invokes simulateTransaction, signing, registration or send methods. It requires success summary, every result, exact bank, fees matching funded packets, positive bounded compute, bounded loaded data, no replacement blockhash and no claimed lookup addresses for v1.

Every overlapping later pre-state must equal the previous simulated post-state byte-for-byte. Initial appearances bind to funding source identities. Readonly/executable state cannot change within a frame. All accounts must be present in the aggregate initial/final view. Wallet full SOL/quote caps and initial custody are independently rechecked from trace pre-state. The Jito default zero-lamport empty system placeholder normalizes to absence; zero-lamport non-system or nonempty accounts do not. Response size is limited to 4 MiB UTF-8.

After replay, complete real source snapshots are read in <=100-account chunks. Each recheck must report one bank; mixed snapshots are discarded and retried at most three times. Own/configuration/custody source identities must remain stable, with only the existing packet-derived shared balance normalization. Mainnet, original lifetime/headroom, 32-slot drift, source expiry, a 30-second deadline and an explicit five-plus-three-per-chunk read budget remain required. Abort-ignoring providers race cancellation and never trigger a replacement simulation.

The retained verifier keeps rpcCollectionRequired=true. The collector can clear that collection flag after its reads, but both retain settlementValidated=false, economicVerificationRequired=true, programDeploymentReviewRequired=true, signingAllowed=false, executionAllowed=false and completeLaunch=false. Snapshot continuity is not financial conservation or proof that the reported trades executed correctly.

## Evidence and verification

- Fourteen selected files passed 173 tests: trace/group funding/assembly, existing holder messages/targets/funding/simulation/settlement/review/signing/execution, client/panel and holder route regressions.
- Final focused trace file passed all eleven cases after explicit empty-lookup metadata and a nonempty-lookup rejection were added. Actual-source TypeScript, four-file typed lint, whitespace checks and production Next build pass.
- Controlled fixtures cover native/SPL/Token-2022 quotes; exact one-call request/bytes; independent reset rejection; failed/incomplete/wrong-bank/resource/fee/lifetime/lookup replies; readonly mutations/default placeholder semantics; context substitutions; >5-packet refusal; source/expiry/network changes; bounded bank rechecks; and stalled-provider cancellation. These fixtures deliberately do not execute BPF or attest trade/rent economics. Shared funding setup was moved into test/pump-launch-group-funding-fixture.ts; funding cases remain unchanged.
- Source contract inspected: https://github.com/jito-foundation/jito-solana/blob/master/rpc-client-api/src/bundles.rs , https://github.com/jito-foundation/jito-solana/blob/master/rpc/src/rpc/bundles.rs and https://github.com/jito-foundation/jito-solana/blob/master/runtime/src/bank/bundle_simulation.rs . The handler selects one bank and provides ordered account snapshots; the runtime carries account overrides between transactions and represents absent accounts using default account data. This describes that inspected upstream producer, not a proven vendor deployment.
- Two empty read-only capability requests used the already configured approved RPC through its existing environment. No wallet address, transaction packet, signature, key value or endpoint was printed or recorded. First HTTP 200 result was inconclusive because its shape was not inspected. A follow-up with explicit confirmed-bank selection returned the expected contextual success envelope with zero results. Sanitized evidence: docs/CODEX-BUNDLE-SIMULATION-CAPABILITY-20261014.json. This confirms empty-method acceptance only, not v1 decoding, sequential trade execution, sendBundle support, latency or funding.
