# Counter evaluation engine checkpoint

13 October 2026. The new lib/counter-trade.ts provides the evaluation core for the requirements in CODEX-COUNTER-TRIGGER-SEMANTICS.md. It is **not yet connected to an API, worker, signing path or UI**. Counter remains incomplete as a usable product feature; the checkpoint supplies code for the real implementation, not a working trading claim.

The evaluator takes the existing on-chain classified movement contract and its saved tape/project context. Transfer/unknown, failed, unsigned-actor, wrong-direction and mismatched block/side evidence cannot create a target. Rate sampling is separate from observed token/SOL size thresholds. SOL filtering requires a classified WSOL/native-SOL quote with nine decimals; another quote asset remains ineligible. Excluded wallets are skipped before sampling. The caller must derive default owned-wallet exclusions from server-owned context; this module does not load an account roster.

Replication uses exact percentages with six decimal places and BigInt token atoms, rounding each contribution down. Accepted contributions accumulate until the independent response minimum is reached. The result is a **token target**, for both Sell and Buy; a Buy target is not a lamport budget, exact-output quote or transaction. No fees, slippage, actual spend or finalized turnover is inferred. Zero/full probability needs no draw, intermediate probability uses rejection-sampled crypto.getRandomValues, and invalid atomic accumulation is rejected before drawing.

The serializable ledger binds project/revision/mint/precision and the exact reviewed rules. Decisions use project/mint/actor/signature identity, so refreshing a provider tape ID/timestamp cannot reroll or double-add a known event. Replayed contradictory chain evidence is rejected. Queue reconciliation checks retained contributions/proposals and probability outcomes. This validates memory/JSON evaluation state, **not durable concurrent storage**; callers must atomically persist a decision and queue before exposing a proposal. The module always returns executionAllowed=false.
