# Owned unsigned session provider/API integration, 21 October 2026

Checkpoint `a51b91c` after `9fc0d41`, followed by the accepted Opus review fixes below. The bounded implementation/review claim is complete and released. This connects the existing session-owned preparation service to actual provider functions and an authenticated API; it does not enable signing or automatic activity.

## Implemented

- `POST /api/wallet-workspace/warmup/session-preparations` requires authentication, exact same origin, JSON and a streamed body capped at 2048 bytes. Its strict request contains only canonical preparation/journal IDs, head/version and literal `prepareRequested:true`. The server derives the action, wallet, amount, captured plan, remaining budgets and original deadline. There is no client callback, arbitrary transaction, signature or finality input.
- The existing service now passes detached trusted plan/document/updated time, head and remaining budget context to the provider callback. Live updated-time mismatch refuses before provider work. Existing atomic binding triggers still repeat exact original document/updated time checks at insertion.
- The callback uses the real `prepareSolanaSwap`, `inspectWarmupSellInventory`, `warmupBuyLink` and `simulateImportedSwap`. Deterministic Buy input must match the action and saved plan. Sell input must match the retained finalized lot's exact current remaining units/decimals, current unfrozen inventory, token program and receipt slot. Source/head/plan/wallet and lot rechecks surround asynchronous reads. The final preparation INSERT also checks Sell remaining units/decimals inside the atomic batch.
- Only `{summary, transaction}` is returned to the existing atomic session writer. Its ordinary preparation, immutable binding and exact unsigned packet remain one transaction. Source-preview/approved-finish/quote/head/SQL-clock guards remain intact. The legacy summary-only callback path is not used by this API.
- Fresh provider calls acquire the existing owner read gate with a 30-second cooldown. A 25-second cooperative request signal and the earlier original review deadline constrain further work, including quote-body reads. This is rate control, not a distributed execution lease or funds reservation. Already accepted remote requests or in-flight database writes cannot be assumed cancelled; original-ID recovery remains required.
- The shared quote reader now cancels a stalled body on abort, checks abort before/after reads and cleans up the reader. Quote amount, route, minimum-output/slippage and expiry predicates are unchanged.
- Successful simulation and complete token metadata are required. The non-wrapped side must establish its token comparison; the wrapped-SOL side's legitimate `null` comparison is preserved. Provisional native spending/output bounds do not grant runtime or custody qualification.
- Fee estimates already include signature/priority/rent. The provisional reserve check uses `max(observed network fee, estimated signature + priority) + estimated rent`, not a sum that counts network fees twice. These estimates are not audited rent or a reservation.
- Saved-only authenticated GET by exact ID recovers after expiry, archival or missing provider key without another quote. Same-ID POST also returns the existing exact result before touching providers; another ID for a bound action returns its recovery ID. Lost batch responses use the original existing recovery path.
- A public allowlist returns review metadata, exact input/expected/minimum output, fee observations, packet availability/hash and false authority flags. Raw packet bytes, plan/proof documents and internal records stay server-side. Errors are fixed/sanitized; cancellation and uncertain writes require same-ID recovery. Nothing retries automatically.
