# Lossless Jito simulation-response reader, 24 October 2026

Base: `ffc9c08`. This is the next source checkpoint after the exact numeric-bank correction. It adds a bounded, lossless simulation JSON reader and local stream-to-economic replay tests. It does not add a provider client or mount a new production path.

## Ownership and implementation

Codex/helper scope is exactly three new files: `lib/jito-simulation-json.ts`, its test, and `test/jito-simulation-stream-flow.test.ts`, plus this handoff/JSON proof. Existing provider/send/signing code, protected Claude UI, AGENTS.md dirt and the seven unfinished warmup draft files remain untouched. This bounded claim finishes at commit.

`readJitoSimulationJson` reads actual streamed UTF-8 bytes before parsing, with a maximum 4 MiB response and optional smaller caller bound. The parser preserves numeric integer tokens exactly as bigint values, distinct from JSON strings, including u64 maximum and negative RPC error codes. It bounds integers to 20 decimal digits before conversion and deliberately refuses fractional/exponent tokens and negative zero. A fraction cannot round into an approved integer amount, and numeric address/base64 tokens cannot turn into valid string values. These restrictions form an explicit simulation-evidence profile, not acceptance of every valid JSON document.

Decoded duplicate keys refuse, including escaped equivalent keys. Objects have null prototypes; `__proto__`, constructor and toJSON are ordinary data. Literal control characters, malformed UTF-8, a BOM and unpaired escaped surrogates refuse. Limits are 32 nested containers, 100000 value nodes, 4096 members per array/object and 100000 stream chunks including empty ones. A stream cannot avoid a finite read budget by endlessly emitting empty chunks. These are input/structure/refusal bounds, not peak-memory or universal route-capacity claims. Field-specific u64, slot, sign and schema checks remain the caller's responsibility.

Cancellation interrupts pending reads, requests stream cancellation without waiting for a stuck underlying cancel callback, removes listeners and releases the reader. There is one abort reaction for the entire body, avoiding per-chunk retained Promise.race reactions. Actual native view geometry determines chunk bytes, so spoofed byteLength properties cannot evade the byte bound. Bytes are copied from private ArrayBuffer backing before decoding; shared mutable backing refuses. Unexpected stream/getReader errors are sanitized using privately recorded fixed reasons, including forged error constructors or mutated genuine messages. Early invalid-option/signal refusal leaves the body with its caller; after acquiring the reader, this function cleans up. Caller-defined stream methods are trusted code, not a sandbox.
