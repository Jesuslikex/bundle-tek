# Bundle listing publication, withdrawal and customer catalog

20 October 2026. Baseline `1fde186`. Implements a separately approved catalog-publication lifecycle for Bundle operators, plus the first-party customer catalog. This is catalog visibility only. Purchases, payment, signing, key delivery and sale eligibility remain unavailable.

## Data and ownership

Saved operator drafts remain immutable private preparation. A new publication review reads the exact owned saved draft and rechecks the current active saved wallet, revision, historical control proof and retained evidence against it. Merely importing a watch-only public address does not make it publishable: a retained ownership/control-proof timestamp is required, with a specific 422 response and useful UI guidance when missing. The insertion guard independently checks that the proof still matches, protecting a deletion/change race. A historical proof is not fresh or exclusive custody, and does not establish that other key copies were erased.

The public subset contains address, exact asking price in lamports, oldest retained activity date, historical sampled balance/time, retained history-check count, unique recorded warmup-signature count and the existing custody disclosure. Internal wallet labels, operator IDs, proof/provider details, saved draft IDs/hashes and private keys are excluded from customer responses. No funding/creation date, activity tier, geographic region, complete chain history, live balance or sale readiness is inferred from these records.

`MARKETPLACE_OPERATOR_USER_IDS` retains exactly the existing validated explicit server-ID policy. Its parsing is shared with catalog selection so publications of unconfigured/revoked operators are excluded. No actual allowlist, provider setting or credential was configured. Every operator API authenticates/authorizes before SQL. Catalog browsing also requires sign-in, without granting a buyer seller access.

## Publication and withdrawal

`/api/marketplace/operator/publications` POST accepts only strict review, publish or withdraw operations, with same-origin JSON and a streamed 2 KiB maximum. Review grants no publication by itself. Publishing requires a second initially unchecked acknowledgement of sharing the exact customer-visible address, asking price and historical evidence. The 60-second manifest binds the saved draft digest and curated public subset with SHA-256. At publish, the server reconstructs that exact reviewed manifest, rechecks the saved wallet/evidence and refuses changed contents or expiry.

Migration `0119_marketplace_publications` adds immutable publications and append-only withdrawals. Its guards bind the parent draft, wallet/revision/metadata, positive exact saved price, retained control proof and exact acknowledgement. A statement-level guard refuses another active listing for the same address across different operator drafts/accounts. One saved draft cannot produce multiple publications. Updates and deletes are refused. Withdrawal has its own exact publication-ID/context acknowledgement and hides the listing from subsequent catalog reads without erasing history. Republishing requires a fresh saved draft and separate review; there is no reuse of withdrawal as publication approval.

Publish and withdraw keep recovery IDs before POST. Unknown outcomes block another write; stop/unmount preserves the reminder and late replies are discarded. Recovery is read-only, by original publication ID or the authenticated owner's unique saved draft, so losing local browser storage need not lose discovery. There is no automatic retry or replacement write. Historical publication records stay verifiable after preview expiry or archival. Visibility separately requires the configured operator, active current wallet revision and no withdrawal. The stored historical data is not an atomic latest-chain assertion or an order reservation.

## Customer UI

Browse wallets now uses `/api/marketplace/bundle-catalog`, which reads Bundle publications rather than requiring an external catalog provider. The legacy provider adapter, API and filter components remain unchanged in source but are no longer the default browse surface. No real provider configuration was changed.

The first-party view supports exact maximum asking price, minimum recorded-activity age, stable price/activity sorting and 20-item local pagination. Unknown activity dates never satisfy a positive age filter. Read-only snapshots expire after 60 seconds without auto-refresh. Withdrawn, archived/revised-wallet and unconfigured-operator listings are excluded from later snapshots. No Buy, Pay, Sign or key-import action is present. Historical balance is not presented as a purchase entitlement or subtracted from the asking price.

Seller copy now distinguishes saved draft snapshots from their separate publication status, avoiding contradictory "not published" and "published" headings. All client checks keep purchaseEnabled, deliveryEnabled and signingAllowed literal false. Protected shell/token layout files are untouched.
