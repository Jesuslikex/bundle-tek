# Jito account performance cost gap

12 October 2026. Current source inspection confirms a remaining accounting gap, not a completed repair.

`app/api/account-performance/route.ts` reads imported swap receipts, their acquisition links, warmup buy receipts and warmup sell receipts in one owner-scoped D1 batch. It does not read finalized Jito bundles or their retained finalization receipts. `lib/account-performance-server.ts` allocates recorded buy cost and sell proceeds using the swap receipts' own network fees. The additional Jito tip transfer is a separate packet and is not included in those values. `components/account-performance.tsx` consequently displays recorded results without these execution costs.

`lib/jito-bundle-server.ts` already retrieves the finalized exact tip transaction during bundle recovery, but its local response type/validation only retains slot, transaction bytes and error status. `lib/jito-finalization.ts` persists exact ordered signatures, slot and manifest identity without the tip transaction's observed network fee. The manifest retains approved tip amount and fee ceiling; a ceiling must not be presented as an actual fee.

## Required repair

Retain exact observed tip transfer and fee evidence, bound to the approved packet, tip payer, recipient, amount and finalized slot. Keep old finalization receipts valid without inventing fees for them. Validate and retrieve retained evidence under the same authenticated owner snapshot as the swap ledger.

Allocate each finalized bundle's execution cost deterministically across its exact constituent swap receipts, with integer arithmetic and a documented allocation rule. Buy allocations become acquisition cost and flow through linked partial sales; sell allocations reduce proceeds. Merely subtracting every bundle's cost from realized results would incorrectly expense open buys. Account/project performance and sale timeline/exports must reconcile, without altering immutable chain receipt documents or double counting the swaps' own network fees. Missing or contradictory expense evidence must be explicit, rather than silently treated as zero. User-performed funded verification still remains necessary.

No application edit occurred during this investigation because the current 978-file full-suite run remains live. Preserve Claude's protected files and existing dirty work. This is the next identified implementation gap after terminal suite verification, while hosted migration recovery remains separately blocked.

## Account performance allocation implemented

The account-performance API now adds Jito bundles, packet signatures and retained finalization evidence to the same owner-scoped D1 batch as trade/acquisition receipts. The expense helper validates historical manifest identity, exact swap receipt/project/preparation/wallet/mint/signature bindings, ordered proof signatures and same finalized slot. Duplicate expense attribution and contradictory or missing finalized swap receipts fail the snapshot rather than returning partial totals. Foreign owner proofs cannot satisfy local owner evidence.

Each observed tip plus its own observed transaction fee is divided equally across the bundle's swap packets. Indivisible residual lamports go to the earliest packets in manifest order. Swap network fees remain in their original immutable receipt documents and are not replaced. Buy expense shares enter acquisition basis; linked partial exits consume that basis using the existing integer allocation rule. Sell shares reduce proceeds. Per-sale timeline costs/results reconcile to the account linked totals, including negative results, and CSV includes separate retained tip, tip-fee and missing-evidence columns.

Bundles with landed saved swaps but incomplete bundle settlement, absent retained proof or an older proof without tip receipt increment a missing-cost count. They do not acquire invented zero-fee evidence. The complete recorded realized result becomes unavailable while known-cost linked totals remain labelled partial. The account UI explains the allocation rule and shows tip/fee coverage separately. Unlanded reviews do not create an expense. This does not establish external activity cost basis, total account return or funded outcomes.
