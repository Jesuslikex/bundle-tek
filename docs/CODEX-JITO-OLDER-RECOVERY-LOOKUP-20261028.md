# Find an older Jito bundle from its recovery file

A user can choose one local recovery file to find an exact owned bundle beyond the 20-row history list. The browser copies one bounded byte snapshot, extracts only lookup identifiers, checks the current project and session, fetches the exact owner-scoped record, verifies the same file's signature against that record, then checks fresh state again. Lookup sends only identifiers to the server. Signed bytes stay local during lookup; a later separately approved registration sends the signed packet to the app server for saving, not network submission.

Reviewed unregistered packets enter the existing non-evicting coordinator, which blocks conflicting bundle actions and retains the existing full-history and initially unchecked approval requirements for registration. Cancelled, expired and already-registered matching packets are inspection/export only. Mismatched signatures, record or history drift, duplicate history IDs, pending collisions and context changes fail closed without automatically signing, registering or sending. Matching cross-tab registration requires fresh exact confirmation before clearing local recovery.

Independent Node 24 focused verification passed 95 tests across the parent/remount and locator files; full TypeScript, scoped typed lint and formatting passed. An independent source review found no remaining blocker after history-gate, stale-action and conflict corrections. A synthetic Chrome fixture using the real component and its scoped CSS showed the expanded controls at desktop and no horizontal overflow at 375 and 320 pixels. The fixture used synthetic context and older global CSS; it did not test a signed-in app, file import, provider or wallet.

The recovery view and pending packets remain in memory and can be lost on a full reload or tab closure. JavaScript temporaries are not guaranteed to be erased, other devices are not synchronized atomically, and an account can change after the final server check. No real wallet, signing, submission, funded action, provider setting or deployment was used.
