# Mobile saved buy cost review and recovery

This continues Proxima parity using the committed `0114` cost storage. The new account panel connects the existing immutable cost service to an authenticated API and an explicit mobile review/save/load flow. It does not admit acquisition lots, consume units, calculate sale profit or enable execution. Application migration/release and real signed-in application verification remain outstanding.

## Product behavior

Saved launch receipts now contain a collapsed **Saved buy costs** panel. Nothing fetches on mount or disclosure expansion. Users can review the selected exact receipt or load all previously recorded buys without a current receipt. A missing/unqualified/poorer snapshot therefore does not remove access to older recorded sources. The main view shows buy quote spending and allocated SOL fees/tip separately. Setup funding, allocation rules, unallocated amounts, wallet rows and hashes remain under **Cost details**. Token-quote amounts never become SOL or assumed dollar values.

Saving requires an unchecked explicit consent box and the exact reviewed receipt/policy/plan hash. Already-recorded origins are not offered as new saves, even if the selected receipt has no separate batch yet. Empty/unqualified snapshots give a recovery path to saved buys and receipt history. Every reload clears approval; context changes abort work and prevent late responses from publishing into the new launch. Loading, stop controls, deadlines, authentication errors, missing storage and invalid responses have explicit states.

A failed, cancelled, timed-out or malformed save response remains unconfirmed. A second save is blocked until an explicit exact-receipt status GET succeeds. There is no automatic retry or POST after recovery. A successful saved-status response can show the original recorded result without another write. The browser counter proof shows GET2/POST1 in the synthetic lost-response flow. Server-side natural receipt/origin identities remain the ultimate duplicate protection.

The child remains usable for saved history when the parent has no currently loaded receipt. One old receipt-panel test now checks that its original receipt actions and the new history action are available instead of assuming every descendant button must be enabled; reviewing new costs is correctly disabled without a receipt. No protected shell, authentication policy, wallet vault or trading controls changed.

## API and client admission

`GET /api/account-launch-activity/purchases?reviewId=...` reads saved-only history. Adding `receiptId` reviews that exact retained snapshot. `POST` accepts only review ID, receipt ID, the fixed policy, the exact plan digest and `approved:true`. Every call uses the existing verified-session `getChatGPTUser` helper and binds owner ID from the session. Caller-supplied owner, amounts, extra fields and duplicate query parameters are refused. Mutations require the same origin and JSON; the streaming UTF8 request limit is512 bytes. Responses are no-store and failures do not expose arbitrary provider/database diagnostics. Requests link cancellation to a60-second budget, with a final cancellation check before response publication. There is no provider or signing dependency added by the endpoint.

The client bounds streamed replies at1MiB and has a65-second deadline and explicit stop action. It admits exact public shapes, review/mint/receipt bindings, canonical integer strings, quote precision, source arithmetic, origin identities, unique source/intent rows, allocation coverage, recorded IDs and all false authority flags. It independently recomputes source/origin/plan digests using a small browser-safe canonical encoder. This checks the public contract, not independent chain provenance; the server still runs the original complete receipt/terminal proof parsers. Raw signed packet data and parent rows are never serialized by this API.

The HTTP DTO normalizes the builder's branded omitted-wallet type to its actual serialized string contract. This was a type-only correction after a scoped lint error; the rebuilt browser JavaScript stayed byte-identical (`work/account-purchases-ui-qa/dto-runtime-proof.json`). No source validation or permission was weakened.
