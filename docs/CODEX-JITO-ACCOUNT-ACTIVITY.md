# Jito account Activity integration

## Current implementation: retained transitions

Each saved bundle review now includes an expandable Recorded bundle timeline. The shared history hook requests only that owned bundle and validates every event against its manifest identity, project, session, revision, fingerprint, declared swap/packet count, tip amount and creation time. Closed timelines do not mount the reader. Opening loads recorded transitions; closing aborts outstanding reads. Manual refresh and older-page controls are included, and changes to the saved state/signature progress/update time refresh an open timeline. This remains a read-only view; baseline recording is available only in account Activity, not through a scoped timeline.

Twenty focused tests across timeline markup/lazy mounting, manifest-bound event checks, account markup, existing Jito review controls and authenticated event routes passed. TypeScript, scoped lint and production build passed. The loading message uses a semantic output element. Rendered browser open/close, pagination and update interaction remain unverified; static markup tests are not browser QA. No new migration, provider request, signing, submission or deployment was introduced by the timeline addition.

The snapshot implementation below has been superseded by immutable Jito events. Migration `0069_amusing_viper` adds an event table, public projection view and database triggers. New bundle reviews, first signature registration for each packet, submission reservation, submitted/finalized outcomes, cancellation and expiry retain their captured bundle state and signature progress in the same database transaction as the originating write. Repeated exact registration does not duplicate the event. Event rows reject updates and deletes. Transaction bytes and individual signatures are excluded from event documents.

Existing bundles without events can be recorded explicitly through the account's Record earlier bundle baselines action. The schema migration performs no backfill. Each click captures at most fifty current saved states as labelled `bundle.baseline` rows; retries skip bundles with any existing event. Earlier transitions are not reconstructed. The authenticated Activity endpoint returns events with owner-scoped event cursors, optional owned-bundle filtering, fifty-row pages and stable timestamp/sequence ordering. GET is read-only and reports whether baseline recording is available. POST requires JSON, matching Origin when present and explicit action-time approval. Activity renders the recorded event time and captured context rather than repeatedly reinterpreting the current bundle. Existing refresh, timeout, abort, older-page and project-link behavior is preserved.

The application journal now contains seventy migrations, 0000 through 0069. The separate hosting candidate still contains the earlier sixty-nine Bundle migrations and has not been repackaged or deployed. Hosted migration recovery is still unresolved. This development migration was tested on disposable databases only; no production or user database migration was run.

The original unpublished migration's bulk baseline INSERT was removed to follow Sites' schema-only migration contract. No live or user database had received that migration. Final correction checks: eighteen tests passed across events/baselines, owner-scoped route/pagination and approved POST behavior, production Activity markup and the full journal on native SQLite and actual disposable Miniflare D1. A fifty-six-bundle fixture verifies batches of fifty then six then zero, owner isolation and unchanged newly tracked bundles. TypeScript, scoped lint and the final production build passed. This does not prove funded execution, rendered browser interaction or hosted readiness.

## Earlier snapshot implementation

12 October 2026. Proxima's live Activity workspace groups execution-related records and links them to projects. Bundle's saved Jito bundles were previously visible only inside the selected trade session. The account Activity screen now includes a Bundles category and latest-state rows linking to the imported project.

The new authenticated GET `/api/imported-projects/jito-activity` reads only the signed-in owner's saved bundles. Pages contain at most twenty records. Creation time plus ID provides stable pagination when state/update time changes; the Activity table sorts loaded records by last update. The existing manifest reader checks captured packet bindings and manifest integrity without provider calls or mutations. Public projections include saved bundle/project/session identity, session revision, fingerprint, swap/packet/signature counts, explicit tip lamports, latest state and timestamps. Transaction bytes and individual signatures are excluded.

The UI distinguishes incomplete review, reserved submission with uncertain outcome, submitted pending finalization, finalized, cancelled and expired records. Complete signature registration alone is not presented as submission. Refresh and independent older-page controls reuse the Activity request lifecycle; requests abort on refresh/unmount and have a ten-second timeout. Errors remain visible without deleting already loaded rows. Archived project bundles remain readable.

These are latest-state snapshots, explicitly labelled in the UI. Prior transitions are not reconstructed, and a complete immutable Jito event timeline remains outstanding. Loaded-page filters are not a global historical search. The imported-project action opens its latest saved workspace, not a guaranteed automatic selection of the original session. No new migration was added; schema 0068 is still required on the host.

Validation: thirteen focused tests across the real-route SQLite fixture, public projection and production Activity rendering passed. Route tests retain the actual Jito/reservation/immutability triggers, test auth/foreign cursor isolation, archived access, payload exclusion, tied-time twenty-plus-one pagination after a cursor timestamp update, generic errors and zero provider calls. Projection checks reject invalid/inconsistent signatures, impossible signed progress, invalid states including coercible arrays and invalid tip ranges. Component checks preserve uncertain outcomes and the older-bundle action. TypeScript and scoped lint passed before the final small state-type guard; final checks/build are recorded in the completion matrix after terminal verification.

Final verification after the state-type guard: all thirteen focused tests passed, TypeScript exited zero, scoped lint exited zero, and the final production build completed successfully with the new API route included. The existing large-chunk warning remains. This is targeted evidence for the account Activity addition, not a rerun of the entire product suite.

Claude's holder/watch components, watch helper, warmup-history test and Vitest configuration were not modified. No credentials, wallet unlock, signing, submission or deployment occurred. Current browser interaction and hosted release remain unverified; the broader Proxima goal is still incomplete.
