## Owned source to observed facts

`inspectWarmupExecutionAssets` requires its caller's server-authenticated owner and first replays that owner's exact current retained review through `readWarmupExecutionSource`. It derives used mint addresses from every retained action, without accepting a mint policy or provider URL from a request. It captures the selection, HTTPS-only configured indexer endpoint and fetcher, checks mainnet genesis, anchors a confirmed slot, and serially reads and rechecks WSOL, every used mint, Clock and Rent. All ten supported plan mints fit one13-account batch; no partition/truncation or stock-specific Clock exception is introduced.

Existing decoders enforce ordinary Clock equality and30-second wall-time consistency, supported raw SPL/metadata-only Token-2022 policy, canonical account bytes and exact integer Rent profiles. Every response meets its minimum floor and stays within32slots of the original anchor. Full policy recheck permits ordinary supply changes but refuses program/decimals/authority/extension changes; Decoded Rent profile bytes and fields must remain exactly equal. Incidental positive Rent-account lamport changes are retained separately and do not change the rent policy. Decoder-replayable account projections are included beside decoded facts, with the exact per-observation evaluatedServerAt used for Clock staleness. This is an in-memory return, not a storage write or complete ledger envelope. The retained original source is reread after the provider work and its exact snapshot digest must match.

Saved-buy Sells must agree with the current mint's actual program and decimals; no classic TOKEN default is added for old records. The existing lot loader already rejects missing token-program economics before retention. An initial test wrongly assumed such a retained legacy review could be created; it was corrected without weakening that loader or leaving a fixture override. Changed incomplete saved source now refuses before any provider call.

The existing bounded RPC reader supplies integer-preserving JSON parsing, pacing, manual redirects and a524288-byte response cap. Non-OK bodies are cancelled and any429 ends this serial attempt without retries or endpoint rotation. Cancellation and the earlier of the original review expiry or25seconds are checked after awaited work and after the final digest. Only the provider hostname is returned; errors are fixed text. No settings/credentials are changed and no real provider read is part of this checkpoint.
