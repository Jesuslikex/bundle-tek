The new `/api/wallet-workspace/warmup/session-consents` route exposes explicit POST operations `review` and `save`, plus same-ID GET recovery. Authentication precedes body/storage access. Writes require exact same origin, JSON and at most2048 UTF-8 bytes. Each operation has a strict allowlist; save requires its own literal approved:true. Request-body owner, unknown authority fields, unchecked approval and unknown operation refuse before database access. The verified session user ID supplies the owner to the real storage service.

Review returns the exact deadline-bound terms without writing. Save requires the exact terms hash and preserves all original insertion-time baseline/expiry rules and false execution/signing/automatic flags. GET requires one lowercase canonical UUID, reads only that owner's record and returns404 for a genuinely absent record without saving or clearing anything. Same-ID idempotent recovery after archival does not approve again. Lost-write recovery remains the service's original single-INSERT/same-ID behavior; this route adds no retry or scheduler.

The response adds the actual original review creation time for strict client admission. A final parameterized owner/review/hash/document-bound SELECT obtains that scalar after service replay; no timestamp or root record is fabricated. No original raw receipt source or key is returned. JSON responses are no-store. Malformed input, cancellation, typed conflicts and unavailable storage have controlled statuses/messages; unexpected HTML/database diagnostics never become public parser text.
