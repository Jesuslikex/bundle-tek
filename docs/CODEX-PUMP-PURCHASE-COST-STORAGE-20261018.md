# Durable launch buy cost sources

This continues the full Proxima parity goal after `31e7d1b`. It connects the deterministic allocation model to real retained owner evidence and immutable local database storage. Purchase review/save UI, acquisition consumption, sale selection and P&L integration remain unfinished. No equivalence or economic readiness claim is made.

## Storage and replay

Append-only migration `0114_pump_purchase_cost_sources` creates receipt-bound batches and globally unique owner/origin sources. One original signed buy has one source, regardless of the number of saved receipt snapshots. The original signature/mint/wallet identity from the preceding allocation policy remains independent of imported workspace and review identity. Amounts stay canonical integer strings; SQL never coerces or sums financial amounts through floating point or signed SQLite integers.

Every batch binds its exact receipt ID, original parent review/signed/signature/state/terminal closure, independently replayed terminal cost report, canonical allocation plan and digest. Admission joins the owner-selected original receipt and signature registration and compares the entire captured parent at write time. The source guard matches the exact source document in its batch plan and rejects a conflicting existing origin, including an `INSERT OR IGNORE` attempt. Update/delete guards protect both tables. Natural receipt and source bounds follow the existing immutable receipt capacity, with explicit8-batch/201-source read limits.

`lib/pump-purchase-cost-service.ts` exposes internal database-only preview, record and history functions. It accepts identities and explicit consent to the fixed policy/plan hash, never caller-authored costs or receipts. It loads the exact primary receipt with the private reader and calls the original `readOwnedPumpGroupRecordedCosts`, including its real terminal/broadcast/observation/signature parsers. It then reconstructs the allocation with the original receipt parser. It captures and rechecks the parent closure around that composition. A changed reviewed plan requires another review; missing finalized tip evidence remains unavailable.

The batch and all source inserts run in one adapter transaction. A failed source insert rolls back the new batch. Repeating a successful request or receiving an ambiguous committed response recovers only a complete independently replayed immutable batch. Cancellation after commit does not erase the records; the exact receipt identity supports a later saved-only read. Simultaneous identical requests converge, and a later snapshot reuses identical source vectors instead of creating more units or rebasing earlier fees.

Preview replays the original batch for each already-recorded origin, with a request-local receipt cache. History replays all original batch plans, reconciles their union against actual unique source rows and verifies each row against its original batch. The common terminal-cost proof is verified once per request and reused only while every receipt context still matches the exact same closed parent. Each primary receipt retains its own original parsing/replay. No cross-request or timed cache is introduced. Thus a newer poorer raw snapshot cannot replace an older source, and missing source rows cannot masquerade as an empty successful history. Incompatible snapshots or retained proofs refuse publication. Parent and cancellation checks run again before publication.

Batch plans are evidence snapshots, not independent expenses to sum. Actual fee payer attribution remains in the preceding payment report. Shared cost policy remains explicit and separate. Setup funding is retained separately, without inferring rent recovery or classifying all creation funding as trade expense. Quote units remain separate from SOL fees and tips. Every acquisition-basis, profit, signing, execution and reservation-change authority remains false. These records are not yet acquisition lots and cannot be consumed by current sale/P&L code.
