## Reproduced problem and fix

The original helper returned a no-op lease when navigator.locks was absent. Auto Sell could therefore reach its vault-unlock and running path without its intended cross-tab exclusion. The new helper refuses unavailable or malformed APIs before unlock. Throwing locks/request getters, synchronous request throws, non-promise returns without a grant and asynchronous rejection receive fixed safe guidance instead of browser error text. No automatic retry is added. After access is restored, another explicit Run click is required.

The successful Web Locks callback still retains its promise until the exact run's release function is called. Null contention still refuses. An older pending run retains its original lock across Stop, project/wallet/lock changes and unmount; a new mount's refused acquisition does not release it. Late acquisition after cancellation still releases its own lease. Run approval, vault/signing/executor, economic limits, runtime guards and receipt rules are unchanged.

Actual mobile fixture inspection found that a start error could be below the scroll area while the fixed footer continued to say settings were complete. The existing footer hint now includes the error and the current disabled reason. This preserves the original single live alert, button conditions and Run aria-describedby. An old lock error therefore cannot hide a newly missing password or another current requirement.

## Limits and boundaries

Web Locks require a genuine standards-compliant browser implementation. They coordinate cooperating contexts on the same origin/profile/partition, not other browsers/devices or globally durable wallet ownership. Tab closure/crash can release a lock while a previously submitted transaction can still land. The app does not use steal; hostile page scripts forging grants or stealing a lock are outside this change. Durable backend reservations and receipt recovery remain essential and unchanged. This does not establish full Auto Sell or Proxima parity or production readiness.

No protected shell/layout, provider/credential/cron setting, migration, application/hosted SQL, actual vault unlock/sign/send, strategy, funded test or deployment occurred. Git deployment remains disabled. Migration0139 is unclaimed and the earlier archive handoff dirt is preserved.
