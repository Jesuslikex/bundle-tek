## Live older-page incompatibility discovered

The follow-up live minute-chart check accepted the current 100-candle SOL page but rejected the older page. HTTP 200 raw-response inspection confirms GeckoTerminal's before_timestamp is inclusive for this pool: requesting 1791848160 returned one candle exactly at 1791848160 followed by 99 older candles and zero later candles. Bundle's public model intentionally requires strictly older pages, so its current provider adapter rejects that real response as an ignored cursor.

A bounded public GET with before_timestamp=1791848159 returned 100 candles, all strictly older than the original boundary, beginning at 1791848100. The intended fix is to translate Bundle's exclusive integer boundary to provider before_timestamp=boundary-1, while preserving its strict post-response validation against the original boundary. This preserves rejection of genuinely ignored/future cursors and avoids duplicate boundary candles or losing one slot to an inclusive duplicate.

Evidence: `live-sol-candle-pages-20261013.json`, `live-sol-candle-cursor-20261013.json` and `live-sol-candle-exclusive-cursor-20261013.json` under work/release-qa. The inconsistent direct-helper cursor contract, rather than all application pagination, was contradicted by runtime evidence.

A separate bounded interval check subsequently passed current 5-minute and daily SOL pages through the same unchanged production provider module: 100 five-minute candles and two daily candles, four GETs all HTTP 200, WSOL quote identity verified.
