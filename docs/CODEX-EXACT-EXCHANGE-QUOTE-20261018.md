# Exact bounded exchange quote reads, 18 October 2026

Production quote preview previously bounded only fetch; response.json ran outside its15-second deadline and had no response size bound. This could leave a production request waiting even though the qualification CLI's outer guard returned. Numeric JSON SOL amounts were also refused, whereas the separate order transport already decodes them from original JSON tokens.

The production preview now bounds fetch and the whole body together to15 seconds, aborts/cancels the reader, rejects late data even from an uncooperative reader, and limits bytes to65536. UTF8 decoding is strict. Only numeric fromAmount/toAmount tokens in canonical plain decimal syntax with at most9 fractional places and10 whole digits are converted to exact source strings. No Number-to-string conversion or tolerance is used. Exponents, negatives, oversized numbers and excess precision refuse. Existing string amount validation, exact requested payout, deposit/payout conservation, expiry, ownership/revision/proof gates and immutable quote storage remain unchanged. HTTP429 is still returned without retry; errors omit upstream payloads. The request remains one fixed-origin GET with no provider order/deposit/signing authority.
