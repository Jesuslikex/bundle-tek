# Exchange order review preparation and recovery API

18 October 2026. The existing internal immutable quote/refund review service is now exposed at `/api/funding/exchange-order-review`. This checkpoint adds backend preparation and recovery only. A visible refund review panel remains next; no approval, order creation or provider transport is exposed.

POST accepts only an exact owned quote UUID and refund public address/revision. It requires sign-in, exact same origin, JSON, a streamed2KBlimit and a5second complete body deadline. Canonical refund validation and separation from the receiving funder return readable400refusals. Existing service and SQL guards require a current active saved draft, exact wallet revisions and proven funder/refund ownership, rechecking context before retaining immutable terms. Identical preparation reuses one review; a different refund requires a fresh quote. Output uses the existing strict public saved-order projection, with every authority flag false and no private provider/rate/deposit reference.

GET accepts one quote UUID and recovers only that owner's existing review or null, without writes, provider calls or requiring the quote to remain live. The saved quote binding is checked again before returning it. This supports recovery if a POST response is lost. Unknown failures explicitly direct saved-review reload before retrying and do not reveal parser/storage diagnostics. All responses are no-store. There is no consent recording, five-second order authorization, order attempt, deposit instruction, signature, send or hold closure in this route. Existing separate approval rules remain unchanged.
